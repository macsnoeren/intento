# Intento API Specification

**Document:** 07_API_Specification.md
**Versie:** 0.1
**Status:** Concept
**Product:** Intento AI Communication Platform

---

# 1. Doel van dit document

Dit document beschrijft de communicatie tussen de verschillende onderdelen van Intento.

Betrokken systemen:

```text
Gebruiker Tablet App

        |

Intento API

        |

--------------------------------

|              |              |

Database    AI Engine    Beheeromgeving

```

---

# 2. API ontwerpprincipes

## 2.1 Veiligheid

Alle API-communicatie:

* gebruikt beveiligde verbindingen;
* vereist authenticatie;
* controleert rechten.

---

## 2.2 Geen directe AI-toegang

De tablet communiceert niet rechtstreeks met de AI.

Flow:

```text
Tablet

↓

Intento Backend

↓

AI Engine

↓

Intento Backend

↓

Tablet
```

De backend controleert:

* gebruiker;
* toestemming;
* context;
* beschikbare data.

---

# 3. Authenticatie

## Login

Endpoint:

```
POST /auth/login
```

Doel:

Een gebruiker of begeleider aanmelden.

Request:

```json
{
 "email":"user@example.com",
 "password":"password"
}
```

Response:

```json
{
 "token":"jwt_token",

 "role":"caregiver"
}
```

# 7. Communicatie sessie API

## Nieuwe sessie starten

```
POST /conversation/start
```

Request:

```json
{
 "userId":"user001"
}
```

Response:

```json
{
 "sessionId":"session001",

 "question":

 "Wat wil je vertellen?"
}
```

---

# 8. Volgende AI-stap ophalen

Dit is de belangrijkste API-call.

```
POST /conversation/{sessionId}/next
```

Request:

```json
{
 "selectedSymbol":"outside"
}
```

---

Backend verwerkt:

* huidige context;
* gebruikersprofiel;
* AAC bibliotheek;
* AI-logica.

---

Response:

```json
{
 "question":

 "Wat wil je buiten doen?",


 "options":[

 {
 "symbol":"walking",
 "image":"walking.png"
 },

 {
 "symbol":"cycling",
 "image":"cycling.png"
 }

 ]

}
```

---


Response:

```json
 "dog"
 ],

 0.91
```

```
POST /conversation/{sessionId}/confirm
```

Request:

```json
{
 "confirmed":true
}
```

---

Resultaat:

* gesprek afronden;
* voorkeur eventueel leren;

# 20. AI Service Interface

De backend communiceert met de AI via een interne interface.

Voorbeeld:

```
POST /ai/next-decision
```

Input:

```json
{
"userContext":{},
"conversationContext":{},
"availableSymbols":[]
}
```

Output:

```json
{
"nextQuestion":"",
"recommendedSymbols":[]
}
```

---

# 21. Foutafhandeling

Alle API's geven consistente fouten.

Voorbeeld:

```json
{
"error":

{
 "code":"USER_NOT_FOUND",

 "message":
 "Gebruiker bestaat niet."
}

}
```

# 22. Real-time communicatie voorbereiding

Hoewel communicatie op afstand geen MVP is, moet de architectuur dit later mogelijk maken.

Voorbereiding:

* events;
* notificaties;
* message queue.

Voorbeeld:

```text
Begeleider vraag

↓

Intento Event

↓

Gebruiker App

```

---

# 23. Samenvatting

De API-laag van Intento zorgt voor:

* veilige communicatie tussen app en backend;
* gecontroleerde AI-toegang;
* gebruikersbeheer;
* contextbeheer;
* AAC-integratie.

De backend blijft de centrale bewaker tussen gebruiker, data en AI.
